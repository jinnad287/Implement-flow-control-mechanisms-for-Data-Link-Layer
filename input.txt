Sending new frames: A nested while loop checks two conditions: 1) Are there still new frames to send? (nextSeqNum < total) and 2) Is there room in the current window? (nextSeqNum < base + N).  If both are true, it calls putOnWire to send the frame, increments the transmission counter, and logs the action.  Crucially, if this is the very first frame in the window (base == nextSeqNum), it starts the timer by recording nowMs() into timerStart and setting timerRunning = true. It then increments nextSeqNum.  Timeout Calculation and WaitingThe code calculates how much time is left before a timeout occurs: rto.getTimeoutMs() - (nowMs() - timerStart).  It uses waitReadable to monitor the socket. This function pauses the program until either an ACK arrives on the socket or the remaining time runs out.  Processing Incoming ACKsIf waitReadable returns true (an ACK arrived in time), the program reads the data using recvfrom.  It deserializes the bytes into an AckFrame and checks if it was corrupted by the channel using isAckFrameCorrupt.  If valid, it reads the cumulative acknowledgment number (ack.ack) into newBase.  If the ACK represents forward progress (newBase > base and newBase <= nextSeqNum), the sender calculates the Round Trip Time (RTT), feeds it to rto.sample() to update the timeout duration, and slides the window forward by setting base = newBase.
